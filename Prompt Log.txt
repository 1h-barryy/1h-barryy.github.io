Yes — that's a completely standard structure. It's called a multi-page site (MPA): separate .html files sharing the same CSS/JS, linked by a persistent nav.
index.html      → Hero / landing
portfolio.html  → Portfolio pieces
barrymade.html  → BarryMade
about.html      → About + contact
assets/
  css/main.css
  js/particles.js
  img/

GitHub Pages serves this directly — index.html is the root, and yoursite.com/about.html just works. No build step, no router.
Tradeoff worth knowing: each page load is a fresh load, so the Three.js particle field restarts on navigation. Two ways to handle it — keep the heavy particle hero only on index.html and give the inner pages a lighter static gradient/canvas (cheaper, still cohesive), or run the particle field on all four and accept a ~1s init on each. I'd recommend the first: it makes the landing page feel like an event rather than wallpaper.

One thing worth knowing about that composer: a static site on GitHub Pages has no server, so a normal form has nothing to post to. Rather than ship a button that silently does nothing, it builds a mailto: and hands the message to whatever mail app the visitor already uses.
